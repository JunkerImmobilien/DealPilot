DealPilot API

01 Was du damit machst

Voller Lese- und Schreibzugriff auf deinen eigenen Objektbestand. Ein Key sieht ausschließlich die Objekte des eigenen Kontos.

Objekte automatisiert anlegen

Investments aus Tabelle, CRM oder Akquise-Tool direkt nach DealPilot.

Bestand synchronisieren

Mieten, Konditionen, Sanierungskosten per PUT spiegeln.

Eigene Dashboards

Objektdaten abrufen und ins eigene Reporting/BI speisen.

Massen-Import

Ganzen Bestand übernehmen — Schleife, je ein POST.

02 Schnellstart

Basis-URL:

https://app.dealpilot.immo/api/v1

Key unter Einstellungen → Account & Sicherheit → DealPilot API (einmalig gezeigt, dpk_live_…).

# Objekte auflisten (Summaries, ?limit bis 500, ?offset)
curl -H "X-API-Key: dpk_live_KEY" …/api/v1/objects?limit=100&offset=0
# Objekt anlegen
curl -X POST -H "X-API-Key: dpk_live_KEY" -H "Content-Type: application/json" \
  -d '{"data":{"plz":"32609","ort":"Hüllhorst","str":"Musterweg 4","wfl":96,"nkm":820,"ek":40000}}' \
  …/api/v1/objects
# Objekt ändern (nur data-Felder senden, die sich ändern sollen ist NICHT möglich — data wird komplett ersetzt)
curl -X PUT -H "X-API-Key: dpk_live_KEY" -H "Content-Type: application/json" \
  -d '{"data":{ …kompletter Datensatz… }}' …/api/v1/objects/OBJEKT-ID

04 Endpunkte

GET/objectsListe als Summaries: Adresse, zuletzt gespeicherter KPI-Stand, Vorschaubild. ?limit (max 500) & ?offset
GET/objects/:idVolles Objekt: komplettes data, Fotos, KI-Analyse, Version
POST/objectsAnlegen — zählt gegen das Objektlimit deines Plans
PUT/objects/:idÄndern — data wird komplett ersetzt; optional expectedVersion gegen konkurrierende Änderungen
DEL/objects/:idEndgültig löschen (kein Papierkorb)

05 Datenmodell — Feldreferenz

Voll durchlässig: data akzeptiert beliebige Schlüssel und gibt sie 1:1 zurück. Die App liest die unten stehenden Feld-IDs — wer sie beim Anlegen befüllt, sieht die Werte direkt in allen Modulen und Berechnungen.
Der schnellste Weg zur vollständigen Liste: Lege ein Referenzobjekt in der App an und fülle die Tabs aus, die du brauchst — ein GET /objects/:id zeigt dir anschließend jede Feld-ID deines Datensatzes 1:1 im data-Objekt. So ist deine Integration immer synchron zur App, auch wenn neue Felder dazukommen.

App-interne Felder (nicht setzen)

Felder mit Unterstrich-Präfix verwaltet die App selbst — z. B. _thumb (Vorschaubild), _avm_state, _mb_state, _immometrica_id, _ueberf_link sowie Caches wie ai_lage_cache und brw_ki_result. Beim Schreiben nicht erfinden und nicht leeren.

Wichtig beim PUT: data wird komplett ersetzt. Deshalb immer Read-Modify-Write: erst GET /objects/:id, die gewünschten Felder im zurückgelieferten data ändern, dann das komplette Objekt zurücksenden — sonst gehen App-interne Felder und Caches verloren.

Die Liste (GET /objects) liefert zusätzlich den zuletzt in der App gespeicherten KPI-Stand je Objekt (u. a. Bruttomietrendite, Cashflow, DSCR, LTV) — praktisch fürs eigene Reporting, ohne das volle Objekt zu laden.

07 Grenzen & Roadmap

Damit du weißt, woran du bist: Die DealPilot-API ist heute eine Daten-API für deinen Objektbestand — bewusst schlank und stabil.

Das kann sie heute

Vollen Lese- und Schreibzugriff auf deine Objekte (CRUD), Summaries mit letztem KPI-Stand, Fotos und KI-Analyse-Text inklusive. Ideal für Import, Sync und eigenes Reporting.

Berechnungen

Deal Score, DSCR, Cashflow und Steuer werden in der App gerechnet. Die API liefert Rohdaten plus den zuletzt gespeicherten KPI-Stand — eine On-Demand-Berechnung per API gibt es noch nicht.

Noch nicht per API

KI-Co-Pilot und AVM-Marktbewertungen, PDF-Export-Erzeugung, Webhooks bei Änderungen sowie Volltextsuche/Filter (aktuell limit/offset).
