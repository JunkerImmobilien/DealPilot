## 4 · Berechnungen

- **Streuungsschwelle 1,55 statt 1,5** (`v1090-WSCH`): Osnabrück-Meppen weist exakt
  1,5 Pp aus und traf die Schwelle punktgenau — Prosa „ab 1,5", Code `stabw > 1.5`.
  *„Eine Schwelle, die genau auf einem abgedruckten Wert sitzt, ist keine Schwelle."*
  (ändert die Regel vom 12.08., siehe [2026-08-12](2026-08-12.md)).
- **Zusammenführung je Datensatz (`v1095-WMRG2`):** v1084a führte Tabelle und Saat je
  **Kennzahl** zusammen; die 493 LZS aus dem Saatlauf vom 12.08. gewannen für die
  ganze Kennzahl, 585 neuere fielen heraus: `2150 − 1078 + 493 = 1565` — geht exakt auf.
  Die Annahme dahinter („die Tabelle ist mindestens so aktuell wie die Datei") stimmt
  nicht: die Datei fährt mit dem Code, die Tabelle wird von Hand nachgezogen.
  Ein Saatlauf ist seitdem nur noch nötig, um eine Ernte **ohne Deploy** wirken zu lassen.
- **Ein multiplikativer Faktor 0 wäre verschwunden** — `if (t && t.wert)` überspringt
  0; für einen additiven Zuschlag harmlos, für einen Faktor eine Katastrophe.

## 7 · Fallen

- **Die überschriebene Projektanweisung** (`fa074a6f`): Marcels Marktbericht-Fassung
  lag als `PROJEKTANWEISUNG.md` im Wurzelverzeichnis und hatte den Haupt-App-Stand
  ersetzt — gleicher Name, anderer Ordner, eine Kopie genügte. `cat >>` hängte
  stundenlang klaglos an die falsche Datei an; aufgefallen erst an zwei identischen
  Byte-Zahlen (160.475). In `43771fe5` sogar mitcommittet. Wiederhergestellt aus
  `56a77fe` (3.490 Zeilen) — nur möglich, weil jeder Rollout committet war.
- **Erst suchen, dann fragen** (`8b0455b0`): Marcel wurde gebeten, die 12.08.-Fassung
  hochzuladen — sie lag als `claude/PROJEKTANWEISUNG.md` längst im Repo (2.605 Zeilen).
  „Siebter Fall dieser Art in dieser Sitzung."
- **v1172b — ein `sed`, das nichts findet, meldet keinen Fehler:** das Muster suchte
  `v=1165`, dort stand `v=1166`; `mb-wizard.js` auf 1172, iframe-URL und Lader auf 1166.
  Der Browser hätte das alte iframe-Dokument aus dem Cache geladen. Nach jedem Ziehen
  alle drei Glieder nebeneinander ausgeben.
- **Veraltete Blockade** (`6a0c0cb2`): die zwei Geldfragen standen noch als BLOCKIERT,
  obwohl beantwortet — fast hätte Marcel sie ein zweites Mal bekommen. Beim Abhaken
  einer Entscheidung den Blockade-Vermerk mitsuchen.
- **Aus dem Marktbericht-Nachtrag:** `v1093-WJG` — zwei Jahrgänge desselben Zweigs
  hielt `waehleAusGruppe()` für zwei Baujahrsgruppen (Potsdam „objektart_nicht_abgeleitet");
  erst Jahrgang (der jüngste gewinnt), dann Baujahrsgruppe. `v1096a-WVOK` — die zwei
  handgeschriebenen Module (Herford, Minden-Lübbecke) lasen nur `sachwert_eur`, das
  Register auch `sachwert`. `land_code` war fest `'NW'` (86 Sätze aus vier Ländern) —
  „wo ein Fehler ausgeliefert wurde, braucht es einen Schritt, der den Schaden sucht"
  (`land-code-reparatur.py`). 17 Dubletten über zwei Pakete: der jüngere Satz gewinnt.
  Zwei Modelle gleichen Zweigs unter derselben AGS/Jahrgang kollidieren → nach Gebiet
  trennen (Kaskade) oder EIN Modell mit Kategorienachse (Hameln-Hannover, Olpe).
- **Werkzeug:** `python3 patch.py | grep -q SKIP` tötet den Doppellauf (SIGPIPE);
  `grep … | cat || echo` kann nie anschlagen; WebFetch bricht nach einer Textmenge ab
  (Seite 21–55), nicht nach Seitenzahl; die Lizenz ist jahrgangsgebunden (NRW-Landesbericht
  2016 `by-2-0`, 2025 `zero-2-0`). Größter Ernte-Hebel: Verwaltungsvorschriften als HTML
  (Brandenburg VV EW-SW, bindend für 18 Gebietskörperschaften).
- **Push abgelehnt:** der Parallel-Chat hatte während des Rollouts vier Commits geschoben;
  `git pull --rebase` gehört abgesprochen.
